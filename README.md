# rest-api-frontend

Фронтенд для каталогу open-source проєктів для новачків. Сторінка бере список проєктів з API бекенду і показує їх картками: назва з посиланням на репозиторій, опис, складність, мови, кількість зірок і організація. Проєкти можна шукати за назвою, фільтрувати за мовою і складністю та сортувати.

Є реєстрація, логін і особистий кабінет. Каталог відкритий для всіх, а кабінет тільки для залогінених: там можна подивитися свій профіль і додати задачу до проєкту. Адмін у кабінеті ще й бачить кнопки видалення задач.

Написано на HTML, CSS і jQuery, без збірки.

## Сторінки

| Сторінка | Що там | Хто бачить |
|---|---|---|
| `index.html` | каталог проєктів з пошуком і фільтрами | всі |
| `login.html` | вхід | тільки незалогінені |
| `register.html` | реєстрація, після неї одразу логін | тільки незалогінені |
| `profile.html` | профіль (username, імʼя, email, роль), форма "Додати задачу", останні 10 задач | тільки залогінені |

У шапці кожної сторінки є меню. Незалогінений бачить "Увійти" і "Реєстрація". Залогінений бачить свій username і кнопку "Вийти".

## Як працює авторизація

- Після логіну `access` і `refresh` токени і дані користувача лежать у `localStorage`.
- Якщо незалогінений відкриває `profile.html`, його перекидає на `login.html?next=profile.html`, а після входу повертає туди, звідки прийшов.
- Залогіненого зі сторінок логіну і реєстрації перекидає в кабінет.
- Запити, яким потрібен токен, йдуть з заголовком `Authorization: Bearer <access>`. Access токен живе 5 хвилин. Коли API відповідає `401`, фронтенд сам шле refresh на `/auth/token/refresh/`, зберігає нову пару токенів і повторює запит. Якщо кілька запитів отримали `401` одночасно, refresh буде один. Якщо refresh теж не пройшов, токени стираються і відкривається сторінка логіну.
- "Вийти" стирає токени з `localStorage`, відправляє refresh на `/auth/logout/` (бекенд додає його в чорний список) і відкриває каталог.
- Помилки валідації з бекенду показуються під відповідними полями форми.

Вся логіка з токенами в `scripts/auth.js`.

Бекенд: https://github.com/zxkeee/rest-api

## Як запустити проєкт

1. Запусти бекенд за інструкцією з його README. Щоб побачити кабінет адміна, створи адміна через `python manage.py createsuperuser`. Він має працювати на http://127.0.0.1:8000, API на http://127.0.0.1:8000/api/v1/.
2. У папці цього репозиторію запусти простий сервер Python:

```bash
python -m http.server 8001
```

3. Відкрий http://localhost:8001 у браузері.

| Що | Адреса |
|---|---|
| фронтенд | http://localhost:8001 |
| бекенд (API) | http://127.0.0.1:8000/api/v1/ |

Фронтенд і бекенд працюють на різних портах, тобто це різні origin. Бекенд дозволяє запити з http://localhost:8001 і http://127.0.0.1:8001 через CORS (`CORS_ORIGIN_WHITELIST` у `config/settings.py`). Якщо запускаєш фронтенд на іншому порту, додай його в цей список, інакше браузер заблокує запити.

Адреса API задана в `scripts/auth.js`, у константі `API_URL`.

Щоб перевірити оновлення токена і не чекати 5 хвилин, запусти бекенд з `ACCESS_TOKEN_MINUTES=1` у `.env`. Через хвилину після входу додай задачу в кабінеті: у вкладці Network буде `401`, потім `token/refresh/` і повторний запит, а логінитися заново не доведеться.
